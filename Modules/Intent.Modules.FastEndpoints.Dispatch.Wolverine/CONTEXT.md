# CONTEXT.md — Intent.Modules.FastEndpoints.Dispatch.Wolverine

## Purpose

Factory extension module that injects Wolverine dispatch logic into FastEndpoints endpoint classes generated by `Intent.FastEndpoints`. This module contains no templates of its own — it hooks an existing template from another module.

---

## Key Architectural Decisions

### Factory extension only — no new templates

This module is a factory extension. It does not generate new files. It modifies `EndpointTemplate` instances produced by `Intent.FastEndpoints` by injecting Wolverine-specific dispatch code.

### One class per operation (not per folder)

`EndpointTemplateRegistration` creates one `WolverineEndpointModel` wrapper per Command or Query that has HTTP settings. Each maps to a single FastEndpoints endpoint class.

This differs from the Controllers, AzureFunctions, and AWS Lambda dispatch modules which group by parent folder element. FastEndpoints uses a one-endpoint-per-operation model because that is FastEndpoints' native convention — each endpoint is its own class. Do not change to folder-grouping here.

### Template filtering via `WolverineEndpointModel` type check

`WolverineEndpointExtension` identifies its targets by checking `model is WolverineEndpointModel`. Only these endpoints get Wolverine dispatch injected; other `EndpointTemplate` instances (non-Wolverine endpoints) are untouched.

### Dispatch: `_sender.InvokeAsync<T>` with and without a request parameter

- Endpoint with a request parameter (`req`): `await _sender.InvokeAsync<T>(req, ct)`
- Parameterless query (no `req`): `await _sender.InvokeAsync<T>(new TQuery(), ct)`
- Void commands: `await _sender.InvokeAsync(req, ct)` (no type argument)

### `IMessageBus` constructor injection with guard

`IMessageBus` is injected via the endpoint constructor (not via `[FromServices]` on `HandleAsync`). An `ArgumentNullException` guard is generated in the constructor. This is consistent with the AzureFunctions and AWS Lambda dispatch modules.

### Priority 2 `OnBuild` callback

The `WolverineEndpointExtension.OnBuild` callback runs at priority 2. This guarantees the extension runs after the base `EndpointTemplate` (priorities 0–1) has established the endpoint class structure and before any lower-priority extensions.

### Mutual exclusivity with MediatR

This module is mutually exclusive with `Intent.FastEndpoints.Dispatch.MediatR`. Both cannot be installed in the same application — they both inject a dispatch mechanism into the same `EndpointTemplate` instances and would produce conflicting `HandleAsync` bodies.

If a developer installs both, they will get a broken SF output. Consider adding a `FriendlyException` in the factory extension if both are detected. At minimum, document this exclusion prominently.

## Interactions with Other Modules

| Module | Relationship |
|---|---|
| `Intent.FastEndpoints` | Provides the `EndpointTemplate` that this extension hooks. |
| `Intent.Application.Wolverine` | Provides the `IMessageBus` abstraction used in generated dispatch code. |
| `Intent.FastEndpoints.Dispatch.MediatR` | Mutually exclusive — install one or the other, not both. |

---

## Anti-Patterns

- **Do not group endpoints by folder.** FastEndpoints is one-class-per-operation by design. The folder grouping from Controllers/AzureFunctions/Lambda does not apply here.
- **Do not inject `IMessageBus` via `[FromServices]` on `HandleAsync`.** Constructor injection with a guard is the established pattern across all dispatch modules in this family.
- **Do not install alongside `Intent.FastEndpoints.Dispatch.MediatR`.** Both mutate the same template instances and will produce conflicting output.
