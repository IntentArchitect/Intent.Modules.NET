### Version 1.0.0

- Breaking Change: this module now owns a generated `WolverineConfiguration` class (`Configure(WolverineOptions, IConfiguration)`) - the single entry point `Intent.Application.Wolverine` and `Intent.Eventing.Wolverine` both contribute a private method and one call statement to, rather than each independently appending its own class's call to the host builder lambda. `Program.cs` now carries exactly one `builder.Host.UseWolverine(opts => WolverineConfiguration.Configure(opts, builder.Configuration));` statement regardless of how many Wolverine modules are installed.
- New Feature: Initial release. Establishes the single, shared `builder.Host.UseWolverine(opts => ...)` registration for an application's ASP.NET host and fixes the order other Wolverine-based modules contribute to it, so installing a second Wolverine module can never silently strand or overwrite the first one's configuration. Contributors call Intent's own `ConfigureHostBuilderChainStatement("UseWolverine", ...)` and are sequenced by factory-extension `Order`; this module also owns the `WolverineFx` package reference and the `using Wolverine` on the host file.
