### Version 1.0.0

- New Feature: The drift engine. It compares the Domain and Services designers' models with hand-written C#, only within the code a `Drift Scope` on the Codebase Structure designer puts in scope, and reports each difference in the application's drift report through Intent.Common.DriftReporting. It reads code and never writes it.
- New Feature: What it checks: classes, attributes, associations (navigation properties), constructors and enums; DTOs, commands, queries, services, service proxies and their operations' return types and parameters; HTTP routes, verbs, parameter sources and authorization, read from ASP.NET Core controllers and Minimal APIs; the file and namespace File Config sets; and relational tables, schemas, primary keys, indexes, foreign keys, column names, types, lengths, precision, defaults and required columns, read from EF Core.
- New Feature: Modules extend the engine through code: a `DriftEngineExtensionBase` factory extension adds claim kinds and vocabulary for any designer, code readers, claim readers, comparers and rules over the model and code together. The engine reads the model and the code for them (an element's linked elements, each method's calls and what their arguments are), so a module brings its rules, not a parser. The engine itself knows no technology; EF Core and ASP.NET Core are extensions built the same way.
- New Feature: The `Drift Scope` stereotype on the Codebase Structure designer's Root Folder and Folders: rows of globs marked In or Out, every Out row with a reason, so tests, scaffolds and vendored code are left out. The drift report holds only drift; what was left out is listed in the Software Factory log.
