### Version 1.0.0

- New Feature: generates CQRS dispatch for the source-generated Mediator library (`martinothamar/Mediator`). Each Command and Query in the Services designer gets a request type and a handler stub that returns `ValueTask`, and `MediatorConfiguration` registers Mediator with a literal pipeline behaviour list, so an application with no behaviours still builds.
- New Feature: the pipeline behaviours are `UnitOfWorkBehaviour`, `MessageBusPublishBehaviour`, `AuthorizationBehaviour`, `LoggingBehaviour`, `PerformanceBehaviour` and `UnhandledExceptionBehaviour`. The logging, performance and unhandled exception behaviours can be switched off with the `Enable logging behaviour`, `Enable performance behaviour` and `Enable unhandled exception behaviour` settings.
- New Feature: `MessageBusFlushOwner` makes the outermost dispatch own the message bus flush, so a command sent from an integration event handler or a domain event handler does not flush the bus early. `Intent.EntityFrameworkCore`, `Intent.Eventing.MassTransit`, `Intent.Eventing.NServiceBus` and `Intent.Eventing.Wolverine` cooperate with it.
- New Feature: handlers are written by an AI agent. The module generates a skill for command, query and integration event handlers, and designer rules on Command, Query and Integration Event Handler tell an agent to revisit the handler when the modelled associations change.
