### Version 1.0.0

- New Feature: The drift engine. It compares the Domain and Services designers' models with hand-written C#, only within the code a `Drift Scope` on the Codebase Structure designer puts in scope, and reports each difference in the application's drift report through Intent.Common.DriftReporting. It reads code and never writes it.
- New Feature: What it checks: classes, attributes, associations (navigation properties), constructors and enums, and domain services, data contracts and repositories (with the entity each repository serves and the class implementing it); DTOs, commands, queries, services, service proxies and their operations' return types and parameters; HTTP routes, verbs, parameter sources and authorization, read from ASP.NET Core controllers and Minimal APIs; and relational tables (whether anything maps them at all, one finding for a table nothing maps), schemas, primary keys, indexes, foreign keys, the multiplicity of an association's unnavigable end, column names, types, lengths, precision, defaults, read from EF Core and Entity Framework 6, a context's conventions for every property of a type included, and attributes' nullability, with `[Required]` and `IsRequired()` where the code's own says nothing.
- New Feature: Java code gets the same checks, read with a .NET parser so no JDK is needed: JPA annotations for the relational checks, Spring MVC annotations for HTTP, and nullability where the code annotates it.
- New Feature: Python code gets the same structure checks, read with the engine's own parser so no Python is needed: classes, dataclasses, enums and protocols, module functions, snake-case names, nullability from `Optional` and `| None` annotations, what each function calls and creates, and Pydantic, marshmallow and msgspec serialized names.
- New Feature: Python web apps are checked with no house module: FastAPI routers and path operations for the HTTP checks (routes under every `include_router` prefix, verbs, parameter binding, status, OpenAPI visibility, security, `response_model`), SQLAlchemy's declarative models for the relational checks and an attribute's `Mapped[T]` type, a `Session`'s `select` and `get` as Entity Actions, and Jinja templates for the User Interface designer (layouts, regions, pages, titles, links, forms and scripts). `Annotated` aliases such as a `Depends` dependency are read as the type they stand for, so a call through one is an invocation, and a plain script's `fetch` straight to an endpoint is a call of that operation. A Python or TypeScript module is named without its file's extension in every designer (`projects`, not `projects.py`).
- New Feature: TypeScript, JavaScript and Vue single-file components are read with TypeScript's own parser on Intent Architect's own Node.js: their types, module functions, Vue components' props and emits, React components with their props, state and JSX, imports through `tsconfig.json` or `jsconfig.json`, and what their code calls. A modelled operation is its camel-case method.
- New Feature: Razor components are read as the C# they compile to, one type with their code-behind: routes, attributes, injected services, `@code` members and what they call, and `@using`s with `_Imports.razor`'s. MVC views and Razor Pages (`.cshtml`) are read the same way, each a component named after its file with its markup, `_ViewStart.cshtml`'s layout kept for its views.
- New Feature: Protobuf `.proto` files (proto2, proto3 and editions) are read: messages, enums and gRPC services, fields with their numbers and whether they can be left unset, rpcs with their streams, and options, and a Service whose class derives from a generated gRPC base (`Basket.BasketBase`) must have that `.proto` service's rpcs as its Operations. A message no file declares and no import brings in is reported missing, even where another message still names it.
- New Feature: Razor markup and Vue templates are read alike: elements, the components their tags name, attributes and directives, and text and values with the code in them.
- New Feature: Modules extend the engine through code: a `DriftEngineExtensionBase` factory extension adds claim kinds and vocabulary for any designer, languages, code readers, claim readers, comparers and rules over the model and code together, and can say what the house's own helpers mean (a string parsed into an enum, a response helper's body) without redoing a framework's checks. The engine reads the model and the code for them (an element's linked elements, each method's calls, their type arguments and what their arguments are, a literal's value included, and the string a value builds, such as a URI put together from fields, interpolation and helper methods), so a module brings its rules, not a parser. The engine itself knows no technology; EF Core and ASP.NET Core are extensions built the same way.
- New Feature: The `Drift Scope` stereotype on the Codebase Structure designer's Root Folder and Folders: rows of globs marked In, Out or Context (read for what it says, never reported on), every Out and Context row with a reason, so tests, scaffolds and vendored code are left out. The drift report holds only drift; what was left out is listed in the Software Factory log.
- New Feature: The `Drift Check` stereotype on the Root Folder turns on opt-in rules that report code the model doesn't describe (files, types, public members, or a module's own rule), with exceptions and severity overrides, each with a reason. A row's Glob is all the type rule needs: `Data/Model/Entities/**` reports every type there the model lacks. One exception row lists several entries, one per line, for one reason, and the list shows each row's entries and reason. An opt-in row's Description says what its files are, and the list shows it beside the rule.
- New Feature: Domain events raised, integration events published and commands sent are checked whatever raises them (`AddDomainEvent`, an outbox, a bus): each modelled link must be borne out by the code, and by default a message type, or a raise of one, that the diagram could show and doesn't is drift. A link says the code can raise the message: a raise in any branch, or of an event a method of the code returns, bears it out.
- New Feature: Entity Actions (create, update, delete and query), Perform Invocations and message subscriptions are checked against the code their source reaches, through repositories, `DbSet`s and generic repositories, in C# and Java. An update is a load then a change, by a method of the entity or by setting its properties, as an EF Core handler does without calling an update or save.
- New Feature: A subscriber's own copy of another application's message, and of each Eventing DTO the message carries through its fields, is checked against the model: every property it has must be one of the fields, of the same type, and the copies are no longer reported as unmodelled.
- New Feature: Coverage: anything modelled that no check reads (an element, a stereotype property, a link) is reported, and what a pack or extension declares non-checkable is listed in the Software Factory log with its reason. A pack that checks something another declares non-checkable overrides it.
- New Feature: An operation's Success Response Code is checked against the success status its handler's code states, through results, status codes and the code's own helpers, a handler returning its data itself being the framework's 200, for ASP.NET Core, Web API 2 and Spring.
- New Feature: A parameter's Header Name and Query String Name, a table's schema (from its folder's or package's Schema stereotype too) and a column's text type are checked, for EF Core, ASP.NET Core, JPA and Spring.
- New Feature: More of the Domain and Services designers is checked: each HTTP operation's security, roles and policy, whether it is an endpoint at all, its API versions, its OpenAPI Settings' OperationId and Ignore (ASP.NET Core's endpoint and route names, OpenAPI callbacks, `ExcludeFromDescription` and `[ApiExplorerSettings]`) and its parameters' types, nullability and defaults; a Command's or Query's result and handler (MediatR, Mediator or Wolverine); enum literals, DTO type parameters and serialized names; owned value objects, ignored columns, association navigability, join columns and a repository's entity and implementation.
- New Feature: A house checks its own stereotypes with a claim reader in its module, asked before the stock readers, so it can also take over a stock reading for its own code; a pack only says what the model states. A module's rule with a stock rule's id replaces it. Three more opt-in rules report interactions the model doesn't show, types an endpoint exposes that no element describes, and values the code states that the model leaves unset.
- New Feature: An index's own name (Use Default Name off) is checked against EF Core's `HasDatabaseName` or named `HasIndex` and JPA's `@Index(name)`, and a default marked Treat as SQL Expression must be EF Core's `HasDefaultValueSql`.
- New Feature: A Domain attribute's Domain Constraints (Required, Text Limits, Collection Limits, Regular Expression, Email, Url, Base64 and Numeric Limits) are checked against the validation attributes on its member: .NET's DataAnnotations and Java's Bean Validation.
- New Feature: Every element is linked to the code its checks verified, for View Code, Open in IDE and Changes Review, leaving out lines with drift and code the model doesn't describe. Requires Intent Architect 5.4.2 or later.
- New Feature: The standard User Interface designer 2.0.0 is checked against Vue, React (with react-router, Redux Toolkit and Zustand) and Blazor: pages and their routes, layouts, components and their regions, stores, view models, services, utilities, behaviours and proxies (where each is, or where its Implementation Path says), their properties, emits and operations, the files an element owns, and what each composes, uses, navigates to and calls, down to the verb and route a proxy operation's request sends, read through the code's own request helpers. A house designer gets the same checks by claiming the stock kinds on its own elements in its pack.
- New Feature: The User Interface designer is checked against Blazor: whether each component is a page or a layout, its routes, title, security and parameters (query, route and bindable), its Regions (`<SectionOutlet>`s, `RenderFragment` parameters, and a layout's `@Body`), the components it uses, the behaviours it applies (a JS interop import, or a script the application loads acting on its markup), the pages it navigates to, the dialogs it opens, the forms it posts to an endpoint and the service proxy operations its code calls, through the code's own services; what a view model or store uses is what its class holds or creates, and a new opt-in rule, `unmodelled.region`, reports a section outlet no Region names. Service proxies are checked against their `HttpClient` and gRPC client calls: verb, route, API version, headers and RPC.
- New Feature: The User Interface designer is checked against ASP.NET Core MVC views and Razor Pages: whether each view is a layout, a page an action renders or a partial, a page's routes (the URLs of the GET actions rendering it, as conventional and attribute routing serve them) and title, its Regions (`RenderBody()` and `RenderSection`, which `unmodelled.region` reports too), the partials and view components it renders, the pages its links reach and the controller actions its forms post to, written with tag helpers, HTML helpers or plain paths.
- New Feature: The User Interface designer is checked against .NET MAUI, its XAML views (MAUI, WPF, WinUI and Avalonia alike) read as the markup half of their `x:Class`: whether each is a layout, page or view, its routes (Shell paths and `Routing.RegisterRoute`) and title, its bindable, query and route properties, its Shell items as Regions (which `unmodelled.region` reports too) with each Composition's Entry label, icon and key, the views it composes, the view model it binds to, the pages it navigates to (`Shell.Current.GoToAsync` or the app's own navigation service), a Persisted store's `Preferences` and `SecureStorage`, and the App Events each element publishes and subscribes to through CommunityToolkit.Mvvm's messenger.
- New Feature: The User Interface designer is checked against Angular: components and their templates (`templateUrl` or inline), the router's tables (`provideRouter`, `loadChildren`, redirects and titles), layouts, pages and dialogs, inputs the router binds from the route or query string and `model()` two-way bindings, and what each component composes by selector, navigates to with `routerLink` or the router, opens with a dialog service and calls through the services `inject()` gives it, `httpResource` requests included. Which route guards secure a page is a house rule's to say, from the guards the engine's route tables give.
- New Feature: A file of an extension several frameworks share, such as `.html`, is read by a framework only where its code names the file or a folder it declares (Angular's `templateUrl`, Jinja's templates folder), and an in-scope file nothing reads is reported as `scope/unread`, to build a house rule for, or to take out of scope or except with a reason.
- Improvement: A proxy's Base URL is checked; TypeScript `Observable<T>` returns, type parameter defaults, enums written as nullable unions or as a constant object's values, and the members of a union of object types are read; a field initializer's calls count as its class's; and a model type that is true but less precise than the code (`string` for `'en'`, `object` for anything) is no longer drift.
- Improvement: More of what Common.Drift checked is checked:
  - keyless entities (`HasNoKey`);
  - whether a navigation is required, where nullable reference types are off;
  - roles and policy set by a custom `AuthorizeAttribute`;
  - foreign keys and store types the code states and the model leaves unset;
  - a new opt-in rule, `unmodelled.index`, for indexes the model lacks;
  - whether every operation's parameters and return may be null, and its parameters' defaults, not only an HTTP endpoint's;
  - the API versions an endpoint serves, and a primary key a class inherits from a modelled base class;
  - a new opt-in rule, `unmodelled.endpoint`, for Minimal API endpoints the model lacks. A modelled class's interface, the classes implementing a service, domain service or repository found as its interface, and a handler's message method are part of what they belong to, not unmodelled code.
- Improvement: A finding says only what disagrees and how to fix it: "`Order.OrderDate` isn't in the code.", "`Shipment` isn't in the model: no Class in the Domain designer describes it.", without how the code was searched or the file and line its link already shows. A navigation that differs only in being a collection or optional says so as its association end's multiplicity: "model `0..1`, code `*`".
- Improvement: The Software Factory log says how long each run took: reading the model, each language and reader, building and reading claims (the slowest kinds), rules and opt-in rules.
- Improvement: Values the code gives as constants it declares are read as their values; anything else it can't read, a line it can't parse, or an index declared twice is reported as can't verify rather than compared as written.
- Improvement: HTTP checks read a parameter's source and an action's verb as ASP.NET binds and routes them (route templates, simple and complex types, registered services, Web API 2's name convention and conventional routes), and also read ASP.NET Web API 2 (`[RoutePrefix]`, `Content(status, value)` and `[ResponseType]`), Minimal API lambda endpoints and what they return, authorization attributes of the code's own and roles given as constants, and gRPC services with their `.proto` messages.
- Improvement: A repository interface that a proxy or client library implements at run time, with no class of the code's own, is verified by the call that gives the interface to its factory or registration (`factory.Create<IOrderQueries>()`, `Bind<IOrderQueries>()`), instead of being reported missing.
- Improvement: A repository, service or domain service whose designer folders name the namespace of its `I`-named interface is that interface, even where a class of its own name sits elsewhere, instead of every same-named element being matched to that one class and its operations reported missing.
- Improvement: An action that succeeds with a value the code doesn't type is checked against its declared `[ResponseType]` or `[ProducesResponseType]` instead of being reported as can't verify, and comparisons, signed numbers and `string.Empty` are typed as C# types them.
- Improvement: ASP.NET Core MVC controllers are read as they're served: conventional routes from `MapControllerRoute` and `MapDefaultControllerRoute()`, an action with no verb attribute answering whichever verb is modelled, `View(model)` returning the view's model, and an action that only redirects returning nothing.
- Improvement: An API whose clients send the version in the query string can model its versions: the versioning scheme is checked only where the Service's Route puts `{version}` (in the path, or in the query string under a name other than `api-version`), so `api/orders?api-version={version}` checks the versions and states nothing about the scheme.
- Improvement: An ASP.NET Core Identity user is mapped by the `IdentityDbContext<TUser>` its DbContext derives from, and has the `Id` and other members `IdentityUser` gives it.
- Fix: A subscriber's own copy of another application's message is no longer reported as a message the diagram doesn't show when the application also owns messages of its own.
- Improvement: A queue consumer that deserializes a message from the body it receives (an Azure Service Bus processor's `JsonConvert.DeserializeObject<T>`) handles that message, and its sends are read from that method; OData controllers are served at their conventional `odata/<EntitySet>` routes; and a property EF doesn't map (`[NotMapped]`, `Ignore`) is never reported as unmodelled, while an attribute modelled for one carries its removal as its correction.
- Improvement: An endpoint or handler that hands a message it receives to code that sends it (`_logic.SubmitAsync(quote)`, then `SendLocal(quote)`) is verified as sending it, instead of the modelled send being reported missing. So is one that sends a local an `out` argument declares (`router.Prepare(id, out ChargePaymentCommand command)` or `out var command`), read as the type it declares instead of as can't verify, and one that hands itself to a library that calls it back (`sync.SyncDirectory(..., this)` running its explicit `IProgress<T>.Report`, which sends).
- Fix: A message the code takes from a contracts package is no longer reported missing when the application keeps its own copies of some of that package's messages in a namespace ending the same way (`Acme.Finance.Contracts.Internal.Commands.Workflow` beside the package's `Acme.Internal.Commands.Workflow`).
- Fix: A Web API 2 controller with no `[RoutePrefix]` is under the conventional route that serves it (`api/{controller}/{id}` puts `DiagnosticsController` at `api/Diagnostics`), and an action serving several verbs (`[HttpGet]` with `[HttpPost]`, an `[AcceptVerbs]` or a `MapMethods` listing several) verifies the modelled verb when it is one of them, instead of reporting the route as unstated and the verb as another or can't verify.
- Fix: A C# type name the file can't reach through its `using`s or namespace is a library's, not the code's own type of that name, so a handler of a contracts package's message is no longer asked to be modelled as a handler of the application's own message of the same name. Projects that add `<Using>` items keep the previous lookup.
- Improvement: A finding the code settles carries the model change that settles it (`Finding.Corrections`): the link a send or publish the diagram doesn't show needs, the removal of a link the code never bears out, the Http Settings an action's code states, the Primary Key a class's key needs, the removal of an empty element no code declares, and the removal of a stale exception. Intent.Common.Drift's move from v1 applies them, so a model clean under v1 is clean on the engine.
- Fix: A type the code leaves out (a JavaScript component's props, a TypeScript `useState(1)`, an unannotated Python attribute) is no longer reported against the model's type: it is listed in the Software Factory log as not stated, as a nullability the code doesn't state is, and a JavaScript function's parameters are compared by name. A member typed by its class's type parameter (`T Value`) verifies against the type argument a derived class gives it (`string` for `UserName : ValidatableObject<string>`) or `object`, as well as `T`.
- Fix: The `unmodelled.member` opt-in rule asks only for what the User Interface designer can state: not a Blazor component's injected service (`@inject`, `[Inject]`, its Uses, checked where the model draws one), a Page property that isn't a route or query parameter (a `[SupplyParameterFromForm]` value), a Store's methods, any member of a UI Service, Utility or Behaviour, a Proxy method's second overload, or a Proxy method that sends no request.
- Fix: C# proxies are checked against the User Interface designer's Call Service Operation Action (the verb, route, API version and gRPC rpc each request sends, also through the application's own request wrapper), and a Store's or View Model's calls of proxy operations are read from its whole class, instead of being reported as can't verify.
- Fix: A file in a project the in-scope code doesn't reference, another application's over the same output folder, is no longer named as one that may hold a missing type, so the type is reported missing.
- Improvement: Folders LibMan installs client libraries into (each `libman.json` destination) are never read, as `node_modules` isn't. A TypeScript or JavaScript file nesting deeper than 64 JSON levels no longer fails every file's read; only a file nested too deep to read fails, alone.
- Improvement: Java and Spring code is read further: a static attribute is found as the constant of its own name (`MAXIMUM_QUANTITY`), JPA's `@JoinColumn` states an association's foreign key, and a handler returning `ResponseEntity<Object>` through the code's own helper (`Http.created(x)`) returns the type of what it passes.
- Improvement: TypeScript is read further: a union of literals (`'light' | 'dark'`, or `(typeof SORT_ORDERS)[number]['value']` over an `as const` array) is an enum, `keyof T` is a `string`, an object type written in place is the model's `object` or a type of its shape, and a Pinia, Redux Toolkit or Zustand store kept in `localStorage` or `sessionStorage` (directly, through VueUse, Zustand's `persist` or Pinia's `persist` option) is Persisted.
- Improvement: JavaScript React class components are read: their props (`propTypes`, `this.props`, destructured or not), state and methods, react-router 5's `match.params` as route parameters, a React Context provider as a Store, a callback prop as an Event Emitter, a module's default-exported object of functions as a proxy, and a route segment such as `v{version}` as the request's version. React's own lifecycle methods, statics and router props are never reported as unmodelled.
- Improvement: Clean-architecture C# is read as C# binds it: `using`s inside a namespace, a controller's `[FromServices]` parameters left out of its operation, a response returned through a presenter's field, a collection class (`CreditsCollection : List<Credit>`) as a collection of its items, a navigation required by its foreign key, and Entity Actions through a modelled Repository's own class or interface. A Domain class's static members, which the designer can't state, and files every type of which a Drift Scope row leaves out are no longer reported as unmodelled.
- Fix: A Value Object attribute mapped by `ComplexProperty` or a value converter (`HasConversion`) verifies as a value, as `OwnsOne` does, instead of being reported as not owned.
- Improvement: ASP.NET Core and EF Core code is read further: an action's `ActionResult<T>` returns `T`, a controller with no `[Route]` of its own is at its base controller's, app-wide authorization (a global `AuthorizeFilter`, `MapControllers().RequireAuthorization()`, the fallback policy) secures what says nothing itself, nested classes (MediatR's `Create.Command`) are each a type of their own, a key in an expression-bodied `Entity<T>(x => x.HasKey(...))` is read, and `IdentityDbContext<TUser>.Users` queries `TUser`.
- Improvement: React and MobX front ends are read further: stores reached through a React context and destructuring, actions handed to an element's event, calls through a module's default export of proxy objects (`agent.Activities.list()`), class stores' created and injected members as Uses and their Web Storage as Persisted, react-router 5's `<Switch>` layouts, route wrappers, path arrays and catch-all routes, a callback prop's argument as its Event Emitter's type, JSX a component renders from a module constant, and its props interface as its own code. A request under a base URL from configuration (`axios.defaults.baseURL = process.env.X`) verifies a route that ends with the one it requests.
- New Feature: ASP.NET Core SignalR's JavaScript client is read: `invoke`, `send` and `stream` call the hub's Operation of that name, and `on("Name", handler)` is the App Event the hub sends, with the handler's parameters as its Properties and a Subscribes from the code that registers it.
- Fix: A Drift Scope or Opt-in Rules row's Glob reads as a File Classification row's does: a line starting with `#` is a comment, a line starting with `!` takes back what the lines above it matched, and the last matching line decides. Before, both were taken as globs that match nothing, so `!` excluded nothing.
