### Version 2.0.0

- New Feature: Updating to 2.0 moves the application onto Intent.Common.DriftEngine. The recipe files become Drift Scope and Drift Check rows on the Codebase Structure Root Folder, and the Guardrails Contracts modules and their stereotypes are removed. The contract files those modules generated stay as hand-written code, code v1 didn't report gets exceptions and Table Names v1 read from EF Core's convention are cleared, so a model clean under v1 starts clean. Installing 2.0 into a Guardrails 1.0.0 application does the same.
- Improvement: The move runs the drift engine on the moved model and corrects the model where the unchanged code settles it. It adds the sends and publishes the diagram doesn't show, removes links the code never bears out and attributes for properties EF doesn't map, gives actions the Http Settings their code states, and drops exceptions that match nothing. A v1 file exception becomes a Context row, so a modelled type in that file is still checked; the projects no recipe ever read (a legacy copy of a project, a test project), and folders of legacy copies of modelled types, get an Out row, and a modelled type declared only there is read for context.
- Improvement: The move excepts the members v1 never compared: a handler's public methods other than those handling the messages it subscribes to, those of a modelled type it generated no contract for, and constructors the model states none of.

### Version 1.0.0

- New Feature: The drift check that compares a designer's model with hand-written code, with its always-on rule and its sync-model, configure-drift-check and validate-drift-recipes skills, shared by every module that contributes a designer to it.
- Improvement: Recipes read UI code: a component's files in one folder (`Checkout.razor` and `Checkout.razor.cs`) are read as one place, the `kebab` and `replace:<text>:<with>` placeholder filters name such files and routes, and interpolated C# strings are read as written.
- Fixed: A type declared with empty parentheses (`public record OrderShipped() : DomainEvent;`) was reported as having parameters the model doesn't; `()` is now compared as the type's parameterless constructor.
- Improvement: Each designer's drift check now reports through Intent.Common.DriftReporting: its findings are its Area (Domain, Services, UI) of the application's one drift report at `.cache/drift/<application>/DriftReport.mdx`, a run with drift fails with one error naming the report, and kinds of fact with no recipe and stale exceptions are warnings in the report. Contributing modules derive their drift reporter from `DesignerDriftReporter`; `DriftReportRunner`, `IDriftDesignerSource` and the per-designer reports are gone.
