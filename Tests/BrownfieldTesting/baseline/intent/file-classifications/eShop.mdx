
# eShop file classifications


The 17 File Classifications on <ModelRef application="eShop" designer="Codebase Structure" name="File Classifications" /> tell a reviewer *what a changed file is for* (the coloured pills in Change Review) and *how closely to look* (its Review Importance). This page lists every file each classification covers. Paths are relative to the repository root.

The chips in the *In the model* column are live links into the designer. The file lists are a snapshot, computed on 2026-10-28 from the entries applied to the model, against the 1146 files under `.` (722 more are out of scope). 1146 of them are classified: **107 High**, 363 Medium, 321 Low and 355 None.

<Callout id="one-row" tone="warning" title="Importance belongs to the file, not to each classification">

Only one entry classifies a file, so a file shows every classification it belongs to at the highest importance among them. For example, `src/Catalog.API/Infrastructure/Migrations/20231009153249_Initial.cs` is High and shows Catalog Items & Stock, Schemas & Startup Migrations at that importance. A reviewer filters by classification and by importance separately, so the file still surfaces under each classification.

</Callout>

<Callout id="defects" tone="risk" title="27 defects found, not fixed by this work">

## Decisions agreed with the team

- High means a developer must review an AI's change to the file, rather than leaving it to AI review. This is the recommended definition, taken without asking: the user chose no questions after setup in /initialize-brown-field.
- Themes were not put to the user for review, for the same reason; they come from four read-only scans of the code, and every High was checked against the code.
- intent/**, .agents/** and .claude/** are out of scope: Intent Architect metadata, module-written agent instructions and local agent tooling.
- Copies of integration events, the basket proto and shared catalog DTOs are Medium, not High: they are shared contracts, and High is kept for silent, serious failures.
