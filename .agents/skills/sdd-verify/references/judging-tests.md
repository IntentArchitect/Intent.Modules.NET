# Judging criteria by test status

Detail for step 2's **Tests** check in `SKILL.md`. Judge each criterion by its test status from `read_spec(slug, artifact: "tests")`:

- **tested** (a confirmed, current binding): run its citing tests narrowly, by the files they sit in (`read_spec(slug, artifact: "tests", requirementId: <its requirement>)` lists them with each criterion's `tests` count, and leaves out a tested criterion's clauses and titles, which nobody re-reads; a targeted or re-verify run passes the requirements it judges in one call, comma-separated; a full verify takes every `testFiles` entry at once), each joined to its `testRoot`: `npx jest <file> -t "spec:<slug> "` (never put the brackets in: `-t` is a regex), or `dotnet test <project> --filter "(FullyQualifiedName~<class>|…)&DisplayName~spec:<slug>" --logger "console;verbosity=normal"`, naming the classes those files declare (so passing tests are listed by name). For Python, Go, Java and Kotlin, run the files verbosely: `pytest <file> -v`, `go test ./<pkg>/ -v -run '<TestName>'`, `gradle test --tests '<Class>'` or `mvn test -Dtest=<Class>`. Gradle and Maven print only failures and counts, so read each test's result from `build/test-results/test/*.xml` or `target/surefire-reports/*.xml`. Match each citation to the test it sits on, above or in, by that test's name, because a comment or docstring citation is not part of the reported name. Run each project once for everything you need from it. These select every test in those files citing the spec, so read each cited title's own result: a cited test that didn't run counts as red, and each criterion's `tests` count is how many results citing it must pass. A build or test command that fails before any test runs because a file it writes is locked or in use by another process (another agent is building) is no result: run it again once, and if it is still locked, report it as blocked rather than as a disagreement. Green is a pass for that criterion. Red is a **disagreement**. Don't re-read the code for it; read just that criterion, by its id, for the failing test's `file:line`.
- **stale** or **unconfirmed** (its wording or a citing test changed since it was confirmed, or it was never confirmed): run the citing tests, then have the **sceptic** below judge each test `read_spec` marks `unconfirmed`. A test marked with a degree (`full`, `partial 1,3/4`, `mismatch`) is already judged against this wording and body: never re-judge it. The sceptic records one binding per judged test.
- **partly tested**: run its citing tests as for tested. The missing clauses are heal's work, not a gap.
- **untestable**: judge it by reading the code (`read_file`), and only when `read_spec(slug, artifact: "verdict")` lists its requirement in `movedSinceVerdict`. Otherwise it holds as judged. A **judged** criterion (an earlier verify passed it by reading the code, as no test cites it) is handled the same way.
- **mismatch** (a sceptic found a citing test asserting what the criterion doesn't say, and neither has changed since): still a disagreement. Read its requirement with `requirementId` for the mismatch's reason and its test's `file:line`, and record it as one again.
- **untested**: report it. It is not a gap: heal writes its tests. In a **full** verify (a spec's first, an extraction's, or one the user asks for), judge its requirement by reading the code like any other: that audit catches defects no test covers. A targeted verify doesn't re-audit it. Passing a requirement judges its untested criteria, so give that result a `reason` naming where the code satisfies them (see **Record the verdict** in `SKILL.md`). When your instructions say heal reported it untestable, give it to the sceptic with heal's reason. Only your sceptics record `untestable`, and only when they agree; otherwise it stays untested.

## Orphan citations

Report every orphan citation (an id that is not one of the spec's criteria, such as a bare `[spec:<slug> R12]`) on the requirements you judge as an observation naming the test, and ask that it cite the criteria it asserts (`[spec:<slug> R12.1, R12.3]`). A citation that names no criterion tests none, so it can never stop a code change counting as out of date.

## The sceptic

Dispatch sceptic sub-agents for the stale and unconfirmed criteria still to judge, and the untested ones heal reported untestable, one per about twelve criteria, grouped by requirement and all in a single response. Use your host's own sub-agent tool when it has one (Claude Code's `Agent`), because those run in parallel; otherwise use `create_sub_agent` with `agentId: "discovery"`.

Give each one the slug and the criterion ids to judge, plus heal's reason for any untestable claim. Have it read each criterion with `read_spec(slug, artifact: "tests", requirementId: <criterion id>)`: that gives its numbered `clauses` and every citing test with its body, the `unconfirmed` ones to judge marked, so it reads code only where a body calls a helper it needs to see. Don't read them yourself to paste into the brief. Have it record its own judgements and return only the mismatches (`criterion · file:line · Checks <what it asserts>; the criterion asks for <what it says>`), each untestable claim it agreed or disagreed with, and any binding still refused. The brief, per unconfirmed test:

> Judge this test against the criterion's numbered clauses, reading its other citing tests too: which clauses does it actually assert? It asserts a clause when it checks part of it and the criterion's tests together check all of it (R28.12), so a clause whose branches are split across tests is credited to each. A test that sets up a case but never checks the outcome asserts nothing. Return `full` when it asserts every clause, `partial` with the `covered` clause numbers (possibly none), or `mismatch` saying what it checks and what the criterion asks for instead, in one positive sentence: "Checks <what it asserts>; the criterion asks for <what it says>", within 300 characters. Return `untestable`, with the reason in a few words (e.g. `visual judgement`), only when no automated test could assert the criterion; for a claim heal made, say whether you agree.

> Then record every judgement with `record_spec_verdict(slug, bindings)` and no `results`, one binding per judged test, naming the test as `read_spec` lists it (`test: "tests/A.test.ts:12"`): `{ criterion, test, degree: "full" }`, `{ criterion, test, degree: "partial", covered: [1, 3] }`, `{ criterion, test, degree: "mismatch", missing: "Checks <what it asserts>; the criterion asks for <what it says>" }`, or `{ criterion, degree: "untestable", missing: "<reason>" }` for a heal claim you agree with. Fix and record again each binding it refuses, except one refused because you changed that test.

The sceptics' bindings are the judgements: don't record them again. The criterion is tested once its tests' bindings together cover every clause. A `mismatch` is also a disagreement, recorded as a gap below.

## Disagreements

A failing citing test, or a sceptic finding that a test asserts something the criterion does not say, is a disagreement: neither side wins by default. Record it as a **`gap`** whose `reason` starts with `Disagreement:`, with `expected` = the criterion's wording, `actual` = what the test and code do, and `location` = the test's `file:line` plus the code it exercises. The Run asks the user once, for all of them, whether to fix the code, change the test or reword the criterion.
