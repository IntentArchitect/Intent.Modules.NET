# Requirements

Each requirement names the principle (P1 to P6 in [the plan](../plan.md)) or the decision it comes from, and the acceptance suite cases that check it. Cases are named by their file under the suite's `Acceptance/cases` folder, by an area (`readers/*`, every file in it), or by a scope, engine or opt-in case (`scope/nested`), meaning every case that shows it. The integrity tests check each exists.

"Must" is a requirement; "may" is allowed but not required.

## Not required

- **Model-only rules.** Naming, "a Layer has a Path", and "a Navigation targets a Page" are designer validation, provided by the vocabulary's own module. The catalog marks them `model-rule`.
- **An inventory of code the model can't state.** Dropped by P1. The catalog marks those checks `dropped`.
- **Coverage summaries of code the model doesn't mention.** Only scope coverage is listed, in the log (R15).
- **The existing evals.** They are not part of the plan and are never run by it.
