# Revert MSMQ — Add SQL Server Transport

Remove the MSMQ transport option that was added in pre.1 and replace it with `SQL Server` transport (`NServiceBus.Transport.SqlServer`). SQL Server transport is cross-platform, uses SQL tables as queues, and fits the existing pattern for SQL-heavy Intent apps.

</RichText>

</Callout>

<RichText id="why-sql">

## Why SQL Server Transport

- **Cross-platform** — works on Windows, Linux, macOS (unlike MSMQ which is Windows-only)
- **No extra broker to run** — queues are SQL tables; any SQL Server instance (including LocalDB for dev) works
- **Natural fit** — Intent apps already use SQL Server for EF Core; adding a connection string is trivial
- **`EnableInstallers()`** auto-creates the queue tables on first run — no manual schema setup

NuGet: `NServiceBus.Transport.SqlServer` v8.x (NServiceBus 9 compatible)

</RichText>

<RichText id="generated-shape">

## Generated Configuration Shape

When `SQL Server` transport is selected, the template produces:

```csharp
var connectionString = configuration.GetConnectionString("NServiceBus")
    ?? throw new InvalidOperationException("ConnectionStrings:NServiceBus is not configured");
var routing = endpointConfiguration.UseTransport(new SqlServerTransport(connectionString));
```

And in `appsettings.json`:

```json
{
  "ConnectionStrings": {
    "NServiceBus": "Server=.;Database=NServiceBus;Integrated Security=true;TrustServerCertificate=true"
  }
}
```

Connection string key: `ConnectionStrings:NServiceBus` — dedicated to the transport, separate from `ConnectionStrings:DefaultConnection` used by EF Core / SQL Persistence.

</RichText>
